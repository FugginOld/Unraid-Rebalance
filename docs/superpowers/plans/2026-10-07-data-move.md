# Data Move Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a **Data Move** tab beside Array Rebalance: tick folders/files (or whole disks) in a Source tree, tick receiving disks, dry-run, start — same engine, lock, progress, pause/stop/abort and log as a rebalance.

**Architecture:** The engine `rebalance.sh` gains `move-plan|move-run`; only its PLAN section branches (a selection planner reads `$RUN/selection.tsv`, written by `action.php`). `browse.php` lists one folder at a time for the Source tree. The dashboard CSS/JS moves into `include/common.css` / `include/common.js`, shared by `Rebalance.page` (tab 1) and the new `DataMove.page` (tab 2) under a new tabbed parent `ArrayRebalance.page`.

**Tech Stack:** bash 5 + GNU coreutils/find + rsync (engine), PHP 8 (endpoints), vanilla JS/CSS in Unraid `.page` files. Tests: `tests/engine_test.sh` (bash, real rsync, php CLI, python3) and a new `tests/syntax.sh` (adds `node --check`).

**Spec:** `docs/superpowers/specs/2026-10-07-data-move-design.md` (approved; decisions D1–D7 are not re-opened here). UI reference: the v3 mockup (already ported into Tasks 8–10 below; executors do not need it).

## Spec corrections

Found against the code; the plan follows the corrected statement.

1. **"Disks come from `status.php` (`disks[]`, already excludes `EXCLUDE_DISKS`)"** — false. `status.php` returns every mounted `diskN`, with `'excluded' => true` on the ones in `EXCLUDE_DISKS`. Data Move filters `!excluded` client-side (`disks()` in Task 9).
2. **"Both pages load [common.css/common.js]"** — kept, but the spec misses that the webGui renders every tab of an xmenu page into **one HTML document** (tabbed and non-tabbed display modes). Consequences the plan handles: (a) element ids must differ per tab — Rebalance keeps `rb-*`, Data Move uses `dm-*`, and the shared code takes the prefix; (b) `common.js` is guarded (`window.RB = window.RB || …`) so the second load is a no-op; (c) **one** status poller serves both tabs — two pollers would each write `status.php`'s `reads.prev` within milliseconds while a move runs and corrupt the "observed write method" sample.
3. **"Active (planning/running/paused, plus `planned` for a move dry run). In Active both panes are read-only"** — taken literally this is a dead end: the selection lives only in the browser, so after a reload in `planned` state the tree is empty *and* locked, and Start would post an empty selection. Plan: panes are read-only in planning/running/paused only. In `planned`, the cards show the dry-run plan (as on the Rebalance tab) until the user changes a tick, then they switch back to the live preview. **Deviation — confirm with the user before Task 9.**

## Decisions made in this plan (not in the spec)

- D2 preference also counts folders placed earlier **in the same plan**, so a series split across several source disks gathers on one destination. Two units from different source disks that would bring a same-named file to the same path are a `PLAN-CONFLICT` (D2: "any file at the same path on both sides").
- A selected path in a share excluded by settings (only possible with a hand-made `selection.tsv`) is a `PLAN-SKIP`, like the rebalance planner. A selected path that resolves outside its disk (symlink), is listed twice, or sits inside another selected item is a `die` (spec: "validated in `action.php` and again in the engine").
- A ticked **file** is always a unit, at any depth. Whole disks expand over shares only (files at the disk root are not share content), using the planner's exact `find` filters via a new shared helper `item_paths`.
- Move-mode empty plan: state `done`, `warn 1`, msg `Nothing can be moved - N item(s) left out (...)` or `Nothing to move - the ticked items hold nothing to move`.
- `browse.php`: one `du -k --max-depth=1` per listing instead of one `du -sk` per child (same numbers, one process); files are sized from `lstat` blocks (what `du` counts). At the disk root, non-folder entries are listed with `excluded: true`.
- Client preview: a ticked disk/share/folder above Item depth whose children are not loaded yet is previewed as one piece (`approx`); the dry run is exact. Dry run and Start need ≥1 ticked item and ≥1 ticked destination; a "won't fit" preview warns but does not block (the engine's D5 error is authoritative). Estimated duration assumes 100 MB/s.
- `rebalance.plg` `launch` entity changes to `Settings/ArrayRebalance` (the spec accepts the URL change).
- `action.php` gets test hooks `RB_RUN`, `RB_MNT`, `RB_CTL` (same pattern as the engine's `RB_*`).
- Syntax checks move into `tests/syntax.sh` (CI calls it) and gain `node --check` for `common.js` and every page's inline script.
- Log lines `PLAN-NOFIT` / `PLAN-CONFLICT` are coloured as errors in the log box.
- Data Move's destination rows use classes `xrow` / `xtrack` (the mockup's `drow` / `track` already exist with other meanings on the Rebalance tab).

## Review Focus

Inputs the spec implies but its test list does not exercise, most likely first; each has a test in the owning task.

1. A file appears at the destination path between the engine's live check and the copy → it is never overwritten, the source copy is kept, the run stops with an error (Task 2).

```bash
############################## DATA MOVE ##############################
SEL_ITEMS=(); SEL_DESTS=(); declare -A FULL_SRC
bad_rel() { [[ $1 == /* || $1 == */ || $1 == *//* || /$1/ == */./* || /$1/ == */../* ]]; }   # true for an absolute path or an empty, . or .. part
read_selection() {   # $RUN/selection.tsv -> SEL_ITEMS ("disk<TAB>rel"), SEL_DESTS, FULL_SRC. The engine does not trust the file: any bad line is fatal
  local kind d rel extra p base a
  local -A seen
  [[ -f $RUN/selection.tsv ]] || die "Bad selection: $RUN/selection.tsv is missing"
  while IFS=$'\t' read -r kind d rel extra || [[ -n $kind ]]; do
    [[ -z $extra ]] || die "Bad selection: a line has more than three fields"
    [[ $kind == item || $kind == dest ]] || die "Bad selection: unknown line '$kind'"
    [[ -n $d && -n ${SIZE[$d]} ]] || die "Bad selection: $d is not an included array disk"
    if [[ $kind == dest ]]; then
      [[ -z $rel ]] || die "Bad selection: a dest line has a path"
      SEL_DESTS+=("$d"); continue
    fi
    bad_rel "$rel" && die "Bad selection: $d/$rel is not a plain relative path"
    p=$(realpath -e -- "$MNT/$d${rel:+/$rel}" 2>/dev/null) || die "Bad selection: $MNT/$d/$rel does not exist"
    base=$(realpath -e -- "$MNT/$d")
    [[ $p == "$base" || $p == "$base"/* ]] || die "Bad selection: $MNT/$d/$rel is outside $d"
    [[ -n ${seen["$d/$rel"]} ]] && die "Bad selection: $d/$rel is listed twice"
    seen["$d/$rel"]=1; SEL_ITEMS+=("$d"$'\t'"$rel")
    [[ -z $rel ]] && FULL_SRC[$d]=1
  done < "$RUN/selection.tsv"
  for a in "${SEL_ITEMS[@]}"; do   # no item inside another: walk each item's parents
    d=${a%%$'\t'*}; rel=${a#*$'\t'}
    while [[ -n $rel ]]; do
      if [[ $rel == */* ]]; then rel=${rel%/*}; else rel=""; fi
      [[ -n ${seen["$d/$rel"]} ]] && die "Bad selection: $d/${a#*$'\t'} is inside $d${rel:+/$rel}"
    done
  done
  (( ${#SEL_ITEMS[@]} )) || die "Bad selection: no item to move"
  (( ${#SEL_DESTS[@]} )) || die "Bad selection: no destination disk"
}
plan_move() {   # Data Move planner - validation only in this task; Task 4 replaces this function
  read_selection
  die "Data Move planning is not built yet"
}
```

```bash
  local a d rel share n dir

      log "PLAN-SKIP  $MNT/$d/$rel  (share excluded in settings)" >&2; (( plan_skipped++ )); continue
    fi
    n=${rel//[!\/]/}; n=$(( ${#n} + 1 )); [[ -z $rel ]] && n=0   # path depth: 0 = the whole disk, 1 = a share
    if (( n == 0 )); then
      for dir in "$MNT/$d"/*/; do
        [[ -d $dir ]] || continue
        share=${dir%/}; share=${share##*/}
        share_eligible "$share" && item_paths "$MNT/$d/$share" "$ITEM_DEPTH"
      done
```

```php
/* Array Rebalance - helpers shared by the endpoints */
function kv_file($f) {
  $out = [];
  if (!is_readable($f)) return $out;
  foreach (file($f, FILE_IGNORE_NEW_LINES) as $l) {
    $l = rtrim($l, "\r");
    $p = strpos($l, '=');
    if ($p === false) continue;
    $k = trim(substr($l, 0, $p));
    $v = substr($l, $p + 1);
    if (strlen($v) >= 2 && $v[0] === '"' && substr($v, -1) === '"') $v = substr($v, 1, -1);
    $out[$k] = $v;
  }
  return $out;
}
function csv($s) { return array_values(array_filter(array_map('trim', explode(',', (string)$s)), 'strlen')); }
/* a path relative to a disk: '' (the disk itself) or names joined by '/', with no empty, '.' or '..' part and no NUL, newline or tab */
function rel_ok($p) {
  if ($p === '') return true;
  if (preg_match('/[\x00\n\t]/', $p)) return false;
  foreach (explode('/', $p) as $part) if ($part === '' || $part === '.' || $part === '..') return false;

}
```

## Risks

- **rsync on the box behaves differently from WSL** → Checkpoint R's `src_f=` value; Branch B covers it.
- **Unraid tab keys or tab ids differ** → Checkpoint R output; Checkpoint A (no tabs, or both pages stacked).
- **`browse.php` is slow on a large share** (one `du` over the whole folder) → Checkpoint B; the Source pane design is then re-decided before Task 10.
- **The client sends the wrong set** (e.g. a partially ticked folder sent whole, which would move unticked data) → no JS test harness; Checkpoint C checks `selection.tsv` line by line. The engine and `action.php` still refuse nested items.
- **Tree re-render cost**: the whole tree is rebuilt on every 3 s poll and every tick; a folder with thousands of expanded children may feel slow → visible in Checkpoint C.
- **Selection is browser-only**: a reload loses the ticks (the last plan/result still shows from the engine).
- **`action.php` writes `selection.tsv` before `rebalance-ctl` refuses a second start**: the running engine read its selection at plan start (atomic rename keeps its open file intact); only a start racing within the engine's first second could read the newer file. The page disables its buttons while a request is in flight.
- **Whole disk / share expansion leaves files that sit above Item depth** (same `find` filter as the rebalance planner) — "empty a disk" can leave such loose files behind; the log's AFTER report shows remaining usage.
- **`du` counts a hardlinked inode once per invocation**, so unit sizes can be under-reported, as in the rebalance planner; live free-space checks still guard each move.
- **The dev build replaces the released plugin on the box** until the user reinstalls the release from the Plugins page.
